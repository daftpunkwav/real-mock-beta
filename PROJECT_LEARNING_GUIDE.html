0.1什么是程序与代码

Part 0 · 软件基础

这一章为完全没有编程基础的同学准备。如果你写过任何一种语言,可以跳过。

前置:无

核心概念

1

程序 = 一组指令

CPU 只懂机器码(0/1 序列)。人类写的 Python / JS / Java 叫源代码,需要编译器或解释器翻译成机器码才能跑。

2

运行时 = 程序跑起来的状态

编译型(C/C++/Rust)先编译再跑,运行快;解释型(Python/JS/Ruby)逐行翻译,慢但灵活。RealMock 用 Python + FastAPI → 解释型,但通过 asyncio 维持高并发。

3

进程 = 一次程序的执行实例

你 python main.py,操作系统就 fork 出一个 Python 解释器进程。RealMock 启动后,3 个 FastAPI 服务都在同一个进程里跑(模块化单体),共享同一份内存与数据库连接池。

RealMock 中怎么用

RealMock 用 uvicorn services.main:app 启动一个 Python 进程,在该进程内由 FastAPI 路由所有 HTTP/WS 请求。进程退出 = 服务停止。

0.2变量、函数、异步

Part 0
ⓘ 前置: 0.1 程序与代码

基础 1:变量 = 命名的内存盒子

每个变量是一块内存,有一个名字(标识符)、一个类型(盒子能装什么)、一个值(当前装的东西)。

# Python(动态类型)
age = 18                 # 整数
name = "小明"            # 字符串
items = ["a", "b"]    # 列表
user = {"id": 1, "name": "Bob"}  # 字典(类似 JS 对象)

// TypeScript(静态类型)
let age: number = 18
const name: string = "小明"
const items: string[] = ["a", "b"]
const user: { id: number; name: string } = { id: 1, name: "Bob" }

基础 2:函数 = 可复用的代码块

def greet(name: str) -> str:
    return f"你好,{name}"

result = greet("RealMock")

函数是一等公民:可以赋值给变量、传参、返回、放进数据结构。

基础 3:异步(为什么需要)

想象你去咖啡店点咖啡:

  • 同步:你站在柜台前等,直到咖啡做好才动。
  • 异步:你点完拿到取餐号,去玩手机。咖啡好了叫号,你再去取。

程序里的"等":是等网络请求、等磁盘读写、等用户输入。异步让一个线程能同时处理很多请求,而不是傻等。

在 RealMock 中的体现

RealMock 用 asyncio(Python 协程)实现"一个线程处理多个 WebSocket 客户端"。详见 4.2 asyncio 协程。

0.4进程 / 线程 / 协程

Part 0
ⓘ 前置: 0.2 变量、函数 0.3 类型

基础 1:进程 = 独立王国

每个进程有独立虚拟地址空间(操作系统给每个进程画一个"假象":你独占全部内存)。进程间通信靠 IPC(管道、socket、共享内存、文件)。

基础 2:线程 = 王国里的工人

同一进程内可创建多个线程,共享堆(heap)但各自有栈。共享变量 = 数据竞争 → 要用锁。

基础 3:协程 = 协作式工人

协程(coroutine)是"可以暂停的函数"。单线程下多个协程通过主动让出实现并发(无锁)。

Python 的 GIL 是什么

Global Interpreter Lock:Python 解释器强制同一时刻只有一个线程执行 Python 字节码(为了简化内存管理)。

后果:Python 多线程不能并行CPU 密集任务,只能并发 IO 密集任务。RealMock 是 IO 密集(Web 请求、STT/TTS 调用、LLM 调用),所以单线程 asyncio 是最优解。

对比

维度进程线程协程
调度者OSOSRuntime(用户态)
并行真Python 中受限 GIL并发(单线程)
通信IPC共享变量 + 锁直接传参
适合CPU 密集IO 密集(Java/Go)IO 密集(Python asyncio)

详见 4.2 asyncio 协程。

0.5内存 / 栈 / 堆

Part 0
ⓘ 前置: 0.4 进程 / 线程

栈(Stack):函数调用链

每调用一个函数,就在栈顶"压入"一个栈帧(含参数、局部变量、返回地址)。函数返回时"弹出"。LIFO(后进先出)。

def A():
    B()
    return "A done"
def B():
    C()
def C():
    print("hi")

A()  # 栈: [A 帧] → [A 帧, B 帧] → [A 帧, B 帧, C 帧] → 弹出 C → 弹出 B → 弹出 A

栈溢出(stack overflow)= 递归太深,栈帧太多超出栈大小。Python 默认栈大小 1MB。

堆(Heap):动态分配的对象

程序用 new、list.append、dict[key]=val 等创建的对象都活在堆上。GC(垃圾回收)负责回收没有引用的对象。

items = []           # items 引用了 [] 对象,[] 在堆上
items.append(1)     # 堆上的 [] 多了元素
del items           # 引用消失 → [] 变垃圾 → 下次 GC 回收

栈 vs 堆

维度栈堆
分配速度极快(指针移动)慢(找空闲块)
大小有限(几 MB)大(受物理内存限制)
生命周期函数返回即释放由 GC 决定
放什么局部变量、参数、返回地址长生命周期的对象

Python 的引用计数

Python GC 主要靠引用计数(每个对象有个 refcount),归零就回收。循环引用(list 内部互相引)走分代 GC。

RealMock 中的内存管理

  • 音频缓冲上限 5MB(interview_service/realtime/voice_pipeline.py),防止浏览器上传 100MB 撑爆内存
  • TTS 队列上限 50 句(_MAX_QUEUE_SIZE = 50),队列超就丢最早的
  • agent_state 每个字段都有上限(weak_points 30 / followup_clues 60),防止 LLM 写到无界

0.6网络基础(TCP / HTTP / DNS)

Part 0
ⓘ 前置: 0.1 程序与代码

OSI 7 层(简化版)

  1. 应用层:HTTP / WS / DNS / SMTP(数据格式)
  2. 传输层:TCP(可靠) / UDP(快)(端口号)
  3. 网络层:IP(路由器之间寻址)
  4. 链路层:以太网 / Wi-Fi(同一网段内传输)

TCP 是什么

面向连接的可靠字节流。3 次握手建立连接,4 次挥手关闭。保证数据按序到达(丢了重传)。HTTP 和 WS 都跑在 TCP 上。

客户端 → 服务端  [SYN, seq=x]                       # 1. 客户端:我想连
服务端 → 客户端  [SYN, ACK=x+1, seq=y]               # 2. 服务端:我同意 + 编号 y
客户端 → 服务端  [ACK=y+1]                          # 3. 客户端:好的,开始发吧

HTTP 是什么

HTTP = "请给我这个 URL 的资源"。

  • 方法:GET(读) / POST(写) / PUT(改) / DELETE(删)
  • 状态码:200 OK / 404 Not Found / 500 Internal Error
  • Header:Content-Type / Authorization / Cookie

HTTP 是无状态协议:服务端不记得你是谁。Session / Cookie / Token 都是应用层加的。

DNS 是什么

把 api.openai.com 翻译成 104.18.32.47。分层:

  • 浏览器 → 系统解析器 → 根 DNS → 顶级域(.com) → 权威 DNS(api.openai.com) → 返回 IP
  • 通常有几秒到几小时的 TTL 缓存

DNS Rebinding 攻击

攻击者控制 evil.com:

  1. 第一次解析返回 1.2.3.4(公网 IP)→ 服务端校验 URL 合法,通过 ✓
  2. 建立 TCP 连接时再解析一次 → 返回 127.0.0.1(localhost)→ 实际打到本机

RealMock 用 DNS Pin 防御:一次解析后锁死 IP。详见 5.2 SSRF 与 DNS Pin。

1.2神经网络基础

Part 1
ⓘ 前置: 1.1 AI / ML / DL 0.2 函数

神经元 = 加权和 + 激活

灵感来自生物神经元:多个输入 → 加权求和 → 激活函数 → 输出。

# 单个神经元的"代码化"
def neuron(x, w, b):
    z = sum(x_i * w_i for i) + b       # 加权和 + 偏置
    return relu(z)              # ReLU: max(0, z)

把多个神经元排成层(layer),多层叠加 = "深度"网络。训练 = 调权重 w 让输出接近期望值。

训练 = 反向传播(Backprop)

"预测错了多少" → 损失函数(Loss)。从输出层往输入层倒推每个权重对 Loss 的贡献 → 用梯度下降更新权重。

不需要懂数学公式,只需知道:训练 = 大量数据 + 反复调权重 + 衡量 Loss 越来越小。

为什么需要"深度"

浅层网络只能学线性关系;深层网络能组合多个简单特征(边缘→形状→物体),表达力指数级增长。

1.3Transformer 架构(Attention Is All You Need)

Part 1
ⓘ 前置: 1.2 神经网络基础 0.2 变量函数(内积)

问题:语言为什么需要"上下文"

"it" 在 "the animal didn't cross the road because it was too wide" 里指什么?人要懂上下文才能猜。模型要懂 → 需要"注意力"机制。

Self-Attention:每个词看其他所有词

对每个 token,生成 3 个向量:

  • Query (Q):"我想找什么"
  • Key (K):"我能提供什么"
  • Value (V):"我的实际信息"

计算 attention = Q·K 相似度 → softmax → 加权求和 V:

# Self-Attention 简化实现(伪代码)
Q = x @ W_q   # (seq, d) @ (d, d_k) → (seq, d_k)
K = x @ W_k
V = x @ W_v
scores = Q @ K.T / sqrt(d_k)         # 缩放防 softmax 饱和
weights = softmax(scores)            # (seq, seq),每行 = 一个 token 的注意力分布
output = weights @ V                 # (seq, d_v),带上下文的输出

Multi-Head:多视角

一组 Q/K/V 只能学一种关系。多头 = 多组 Q/K/V 并行,每头关注不同方面(语法、语义、长距离),最后拼接。

# Multi-Head Attention
heads = [self_attention(x, W_q_i, W_k_i, W_v_i) for i in range(n_heads)]
output = concat(heads) @ W_o

Transformer Block = Attention + FFN + 残差 + Norm

# 一个 Transformer block(简化)
x = x + MultiHeadAttention(LayerNorm(x))    # sublayer 1 + 残差 + 预归一化
x = x + FFN(LayerNorm(x))                  # sublayer 2 + 残差 + 预归一化

为什么 Transformer 改变了 AI

  • 并行:不像 RNN 必须等前一个,所有 token 同时算
  • 长距离:任意两个 token 直接相连(O(1) 距离)
  • 可堆叠:堆 96 层就是 GPT-3;堆 1000+ 层就是前沿 LLM

GPT vs BERT

  • GPT = Decoder-only(只看上文,适合生成)
  • BERT = Encoder-only(看双向上下文,适合理解)
  • T5 / BART = Encoder-Decoder(翻译、摘要)

RealMock 用任何"openai_chat / anthropic_messages / openai_responses"协议的模型(基本都是 Decoder-only)。

进一步阅读:论文 Attention Is All You Need(Vaswani et al., 2017)。Weaviate RAG 入门 对 RAG 与 Transformer 关系讲得很清楚。

1.4LLM 基础:它是怎么"思考"的

Part 1
ⓘ 前置: 1.3 Transformer

LLM = 下一个 token 预测器

LLM 训练时做"给定前文,预测下一个 token"。没有"思考"或"推理",只是统计意义上的"最可能下一个"。

三大阶段

  1. 预训练(Pre-training):用万亿 token 文本训,学"语言规律"。成本千万美元。
  2. 微调(Supervised Fine-Tuning, SFT):用人工标注的"指令-回答"对训,让模型"听指令"。
  3. RLHF / DPO:用人类偏好排序训练奖励模型,让模型回答更"有用 / 安全"。

为什么"涌现"会出现

模型大到某个临界点(参数 ~10B+,训练 token ~1T+),原本不会的能力突然出现:多步推理、代码生成、思维链。这是 LLM 最反直觉但最强大的特性。

关键参数

temperature
采样随机性。0 = 永远选概率最高的(确定);1 = 按概率采样(更"有创意")
top_p
只从概率前 P% 的 token 里采样;截断长尾
max_tokens
最多生成多少 token(单次响应上限)
context_window
上下文窗口大小(LLM 一次能看多少 token,128k 是常见上限)
frequency_penalty
重复惩罚(防止模型说"嗯那个那个")
presence_penalty
主题新鲜度(鼓励引入新话题)

    payload = {
        "model": self.model,

1.5Tokenization & Embedding

Part 1
ⓘ 前置: 1.4 LLM 0.2 变量

前置:为什么不能直接喂字符串

神经网络只懂数字。第一步必须把文本转成数字序列。这叫tokenization。

BPE(Byte-Pair Encoding)

最常用的算法。从字符出发,反复合并"出现频率最高的对"。最终:高频词一个 token,低频词拆成多个 token。

# BPE 合并过程(示意)
# 语料:low lower lowest new newer
# 初始: l o w _ l o w e r _ l o w e s t _ n e w _ n e w e r
# 第 1 步合并 e r → er
# 第 2 步合并 er _ → er_
# 第 3 步合并 n e → ne, ne w → new
# ...
# 最终: "low" / "lower" / "lowest" / "new" / "newer" / "newest_ly"

Token 与字符的关系

经验值:中文 1 字 ≈ 1.5 token;英文 1 词 ≈ 1.3 token;代码 ≈ 0.5 词/行 ≈ 5-10 token。这正是 RealMock 估算 token 的依据:

    if not text: return 0
    return max(1, int(len(text) / 1.5))   # 中文 1 字符 ≈ 1.5 token

Embedding = token → 高维向量

token id 是整数(0, 1, 2, ...),但整数没有"含义"。Embedding 把每个 token 映射成高维向量(GPT-3 用 12288 维,Claude 约 8000 维),使"语义相近的 token 在向量空间里也近"。

# Embedding 矩阵 = 大表 (vocab_size × d_model)
# token 5 → 第 5 行 = [0.12, -0.45, 0.88, ...]

Embedding 的两大用途

  1. 作为模型输入:第一层把 token id 查表成向量,送进 Transformer
  2. 语义检索:把文本编码成向量,计算"语义相似度"(见 1.6 RAG)

RAG(Retrieval-Augmented Generation)是什么

让 LLM 在回答前,先从外部知识库中检索相关文档,把"问题 + 检索到的文档"一起塞进 prompt。

两阶段流程

阶段 1:Ingestion(预处理,离线)
  文档 → 切块(chunking) → embedding → 存入向量数据库
  例子:7 家公司 × 4 切片 = 28 条

阶段 2:Inference(推理时,在线)
  用户 query → embedding → 向量数据库相似度检索 → top-K 文档
  → 与 query 一起塞进 prompt → LLM 生成回答

向量数据库 = 高维向量的搜索引擎

传统数据库(B-Tree 索引)擅长精确匹配;向量数据库(HNSW 索引)擅长"找最近邻"。常见:Chroma / Milvus / Pinecone / Weaviate。

2.3Hooks 原理(规则、为什么有)

Part 2
ⓘ 前置: 2.2 JSX / 组件 0.4 协程 / 调用栈

前置:React 用"调用顺序"识别 Hook

React 内部为每个组件维护一个 Hook 链表(Linked List)。每次渲染按调用顺序挂节点:

组件首次渲染:
  useState("Bob")     → 链表第 1 节点: {value: "Bob", setter}
  useEffect(fn, [])   → 链表第 2 节点: {fn, deps: []}
  useState(0)         → 链表第 3 节点: {value: 0, setter}

组件 re-render 时:
  useState("Bob")     → 取第 1 节点的值
  useEffect(fn, [])   → 取第 2 节点
  useState(0)         → 取第 3 节点

两条规则(都不是"官僚主义")

❌ 不要在 if / for / 嵌套函数里调 Hook

因为 React 靠"调用顺序"对应"链表节点",条件调用会让"这次调的第 N 个 Hook"映射到"上次第 N 个 Hook"的节点 → state 串了,error: "Rendered fewer hooks than expected"。

✅ 解决:把条件放进 Hook 里面

// 错
if (loggedIn) { const [n, setN] = useState("") }   # 顺序漂移
const [c, setC] = useState(0)

// 对
const [n, setN] = useState("")   # 永远按同一顺序调
const [c, setC] = useState(0)
if (loggedIn) { setN("x") }          # 条件在 Hook 后面

✅ 只在 React 函数里调

类组件、普通 JS 函数、事件 handler 内不能调。ESLint 插件 react-hooks/rules-of-hooks 会自动检测。

为什么用链表而不是 Map/WeakMap

链表简单、显式、O(1) 追加;Map 需要键名,但 Hook 故意不让你起名(防止用户依赖名字,鼓励按位置匹配)。

2.4useState / useEffect

Part 2
ⓘ 前置: 2.3 Hooks 原理

useState = 组件的"局部变量"

const [count, setCount] = useState(0)
// count: 当前值
// setCount: 修改函数(触发 re-render)

<button onClick={() => setCount(count + 1)}>{count}</button>

关键:改 state 一定触发 re-render(不是直接改 DOM,React 内部 diff 决定怎么改)。

useEffect = 副作用钩子

"副作用" = 渲染之外的事(网络请求、订阅、DOM 操作、计时器)。

useEffect(() => {
  // 1. 每次 mount 后跑
  // 2. 每次 deps 变化时,先跑 cleanup 再重跑
  // 3. 组件 unmount 时跑 cleanup
  const sub = ws.subscribe(handler)
  return () => sub.unsubscribe()   # cleanup
}, [sessionId])

依赖数组 3 种写法

  • []:只在 mount + unmount 时跑
  • [a, b]:a 或 b 变化时跑
  • 不传:每次 render 都跑(几乎不要用)

cleanup 在什么时候跑

  1. 组件 unmount(卸载)
  2. 下次 effect 跑之前(deps 变了)
  3. Strict Mode 开发环境:挂载→卸载→再挂载(故意双调用)

Strict Mode 双调用的真实案例

React 19 升级后有团队报告 useEffect cleanup 漏跑导致 1.2GB/h 内存泄漏。原因:cleanup 涉及微任务时,React 19 把 cleanup 推迟到微任务队列排空后,组件已经 unmount,interval 还在跑。

教训:cleanup 一定要同步 + 立即释放。RealMock 的 useInterviewWS 在 cleanup 中 ws.onclose = null; ws.onerror = null; ws.onmessage = null; ws.close(1000),正是这个模式。

def encrypt_secret(plaintext):
    if plaintext.startswith("enc:v2:"): return plaintext  # 已加密
    salt = os.urandom(16)       # 16 字节随机盐(防彩虹表)

为什么 nonce 重复会灾难

GCM 安全性基于 (key, nonce) 唯一。如果同一 nonce 加密两个明文,攻击者可恢复明文异或 + 伪造 tag。RealMock 用 os.urandom(12) = 96 bit 随机,生日攻击需要 2^48 次才碰撞。

为什么 PBKDF2 200k 迭代

OWASP 2023 推荐。每次派生 ~250ms。GPU 暴力破解 8 字符密码:1k 迭代 → 10^8/s,200k 迭代 → 500/s。

prod 必须显式设 SECRET_KEY

def check_rate_limit_by_id(*, key, client_id, limit, window_seconds=60):
    bucket = _BUCKETS.get((key, client_id))
    now = time.monotonic()
    while bucket.timestamps and bucket.timestamps[0] <= now - window_seconds:

CAP 定理

分布式系统三选二:

  • Consistency:所有节点同一时刻看到同一份数据
  • Availability:每个请求都能收到非错响应
  • Partition tolerance:网络分区时仍能服务

P 必选(网络一定会断),所以 CP 或 AP。

为什么只能二选一

网络分区时:节点 A 收到写入,但 B 不知道(因为不通)。要 C → 拒绝 B 的读(丢 A);要 A → 各自服务(暂时不一致)。

BASE 理论

放弃强一致,换可用性:

  • Basically Available:基本可用
  • Soft state:软状态(允许中间不一致)
  • Eventually consistent:最终一致

3 大一致性模型

模型保证例子
强一致写完立刻读到最新值etcd / ZooKeeper(CP)
因果一致有因果关系的操作有序聊天(自己消息按序)

AI / Agent Q1-Q12

❓Q1. 什么是 Token?为什么中文 1 字 ≈ 1.5 token?答案在 1.5

✅A:Token 是 LLM 的最小处理单元(BPE 等算法切出)。中文在 BPE 中平均 1~2 个 token,因为常用字 1 个、生僻字 2~3 个,所以 1.5 是经验估值。RealMock 用 len(text)/1.5 估算 context 占用,在 30% 阈值就触发压缩。

❓Q2. 讲一下 Self-Attention 原理。Q/K/V 各自是什么?答案在 1.3

✅A:对每个 token 算 3 个向量:
- Query (Q):这个 token "想找什么"
- Key (K):这个 token "能提供什么信息"
- Value (V):这个 token "实际携带的信息"
计算 attention = softmax(Q·K^T / √d_k)·V。缩放因子 √d_k 防止点积过大导致 softmax 梯度消失。Multi-Head Attention 用多组 Q/K/V 并行,每头关注不同方面。

❓Q3. RAG 的两阶段是什么?距离阈值有什么作用?答案在 1.6

✅A:
- 阶段 1 Ingestion(离线):文档→切块→embedding→存入向量库
- 阶段 2 Inference(在线):query→embedding→相似度搜索→top-K 文档→与 query 拼成 prompt→LLM 生成
距离阈值:RealMock 设 distance < 0.5 才用,弱匹配丢弃。不设的话,弱相关文档会污染 prompt,反而降低答案质量。

❓Q37. 进程 vs 线程 vs 协程?答案在 0.4

❓Q41. 乐观锁 vs 悲观锁?答案在 4.3

❓Q43. 一致性哈希?为什么需要?

✅A:普通 hash(key) % N 在 N 变化时(加/减节点)几乎所有 key 都要重新映射(缓存雪崩)。
一致性哈希:把 hash 值映射到 0~2^32 圆环,节点也映射到圆环,key 沿环找到最近的节点。增删节点只影响相邻一小段。
常用于分布式缓存(Redis Cluster)、CDN、负载均衡。

❓Q44. 漏桶 vs 令牌桶?答案在 5.1

✅A:
- 漏桶:请求排队,固定速率出。无法应对突发
- 令牌桶:固定速率往桶里加 token,每个请求消耗 1 个。允许"突发"

❓Q45. CAP 定理为什么只能二选一?答案在 5.3

✅A:P(分区容忍)必选:实际网络一定会分区。要 C(强一致)→ 拒绝部分写/读,失去 A;要 A → 各节点独立服务,牺牲 C。
现实系统是 AP + 最终一致(如 DynamoDB / Cassandra)或 CP(如 etcd / ZooKeeper)。

❓Q46. Raft 与 Paxos 区别?

✅A:Paxos 太晦涩难懂,各种变体难以推理。Raft 设计目标 = 易理解:① 强领导(任何时候最多 1 个 leader);② 任期(term)单调递增;③ 日志复制 = leader 把日志条目发到所有 follower,过半确认才提交。
Raft 三子问题:领导选举、日志复制、安全性。
etcd / Consul / TiKV 都用 Raft。

❓Q47. 什么是 2PC?它阻塞在哪?

✅A:两阶段提交:① 协调者问所有参与者"能不能提交",参与者锁资源写日志回 OK;② 协调者发"提交",所有参与者提交。
阻塞点:协调者在第一阶段后崩溃 → 参与者锁了资源但没人说"提交还是回滚",永久阻塞。
3PC引入预提交+超时,但仍有边界情况。
实际:分布式事务普遍用最终一致(Saga / 事件溯源)而非 2PC。

❓Q48. 什么是 TLS 1.3 的 0-RTT?

✅A:传统 TLS 1.2 至少 2-RTT。TLS 1.3 简化为 1-RTT(客户端在第一帧就发密钥共享)。
0-RTT:如果客户端之前连过,可在第一条消息就发加密数据(用 PSK 密钥)。代价:可重放攻击(中间人重发第一帧),所以只用于幂等请求(如 GET)。

✅A:① 短期(messages):当前会话;② 长期(DB / 文件):跨会话;③ 结构化(字段):weak_points、asked_questions;④ 检索(RAG):相关记忆当工具调出。
RealMock 三层都用:agent_state 字段、prep_sessions.messages、system_learning.json 跨场次反哺。

❓Q51. WebSocket 心跳为什么 30s?答案在 3.3

✅A:① 太短浪费流量;② 太长发现断线慢;③ 主流 LB(Nginx / Cloudflare)默认 60s idle timeout,留 30s 缓冲。
RealMock 客户端 30s + 3 次 miss ≈ 90s 才发现断线,生产可接受。

❓Q52. 如何防止 LLM API Key 泄漏?答案在 4.5

✅A:① BYOK 加密落库(AES-256-GCM + PBKDF2);② 出站前脱敏(RedactFilter 替换 sk-/Bearer);③ 不存前端(Cookie HttpOnly + Secure + SameSite=Lax);④ SSRF 防御;⑤ 旧格式检测(enc:v1 拒绝静默迁移);⑥ 轮转(定期更换 master key)。

❓Q53. 为什么 RealMock 不用 Postgres?SQLite 的极限在哪?答案在 4.3

✅A:本地优先、零运维、文件即库。SQLite 上限:① 单写者(WAL 缓解);② 无网络;③ ~ 1 亿行/库;④ 无内置复制/分片。
切到 Postgres 的信号:并发写入 ≥ 5/s、数据量 > 100GB、需要跨实例访问。RealMock 用 SQLAlchemy 2.0 抽象,DATABASE_URL 即可平滑迁移。

❓Q54. 单页面 940 行的"上帝组件"如何重构?答案在 2.6

✅A:① 按业务域切(features/interview/{hooks,components}):
  - useInterviewRoom:会话生命周期
  - useInterviewAudio:录音 + TTS

⑤ 避免 Context(全 props + hooks 传)。

❓Q55. 实时系统的"数据一致性"如何保证?答案在 5.3

✅A:
RealMock 场景:WS 写状态、报告生成、GET 报告页三路并发:
① 幂等:同一操作可重入不破坏(报告生成用 CAS 哨兵)
② 状态机:状态转移有合法集合(pending → active → completed)
③ 锁:进程内 asyncio.Lock + DB 哨兵
④ 最终一致:不追求 100% 准确,允许短暂不一致

❓Q56. 估算 LLM 服务成本上限?

✅A:① 单次成本 = prompt_tokens × input_price + completion_tokens × output_price;② 用户数 × 平均会话数 × 平均回合 × 平均 tokens;③ 加 buffer 30%(系统 prompt + 工具结果);④ 限流配额 + 告警;⑤ 自建 token 计数器 + Prometheus;⑥ RealMock 限流:LLM 10/min、session_create 20/min。

❓Q57. 微服务 vs 模块化单体?RealMock 选了哪个?答案在 0.1

✅A:
微服务:独立部署、独立伸缩、技术栈异构;代价:运维复杂度、分布式事务、网络不可靠。
模块化单体:一个进程,模块边界清晰,各自 main.py 可独立启动,演进到微服务时改 base URL 即可。
RealMock 选模块化单体:api_service / agent_service / interview_service 业务零循环,仅共享 shared/。

❓Q58. 怎么测试 LLM 应用?答案在 1.8

✅A:① 单测:工具函数(检索、解析、压缩)、纯逻辑(followup.analyze);② 集成:整链路 + WS;③ Contract 测试:用 fake LLM 测"如果返回 X,系统行为 Y";④ 稳定性:固定 seed、相同输入多次跑结果一致;⑤ 回归:用"好回答"基准集;⑥ Eval:不靠 LLM 自评(主观、漂移、贵)。

❓Q59. 解释一下 RealMock 的"系统级学习反哺闭环"如何工作?答案在 1.8

✅A:
