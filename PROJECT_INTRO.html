01 · 项目定位

01这到底是个什么样的项目?

RealMock = Real + Mock Interview。顾名思义,它不只是一份题库, 而是想「把真实面试尽量搬进浏览器里让你反复练」。 它的产品承诺写在 apps/web/src/app/page.tsx 首页 hero 上: 用真实流程,练好下一场面试。

TL;DR — 一句话总结

📌 RealMock 是一个本地优先、BYOK(自带 API Key)的 AI 模拟面试系统。

你上传自己的简历,选一家想面的公司(字节 / 腾讯 / 阿里 / 美团…), 选岗位和职级,启动一个会说话、有表情、能打断你、还能追问的 AI 面试官。 面试完它给你一份报告、追问你薄弱的知识点,下次面试还会把这份记忆带过去。

▍它解决什么问题?

真实面试里你很难在短时间内体验到「被问倒 + 临场反应 + 表达组织」这一整套肌肉记忆。 题库型工具给的是「背题 → 默写」,RealMock 给的是「被追问 → 思考 → 表达」这个回路。

  • 出题不是死题库 — 题目由 LLM 根据你的简历和目标公司实时生成,不刷固定题库
  • 会追问 — 你回答含糊,面试官会顺着你的用词往下挖,贴近真实面试节奏
  • 企业风格可切换 — 字节、腾讯、阿里这种公司风格都做了不同的人格 / 风格选项
  • 音视频交互 — 摄像头 / 麦克风都在用,候选人侧的人脸状态会进 LLM 提示词
  • 报告 + 成长闭环 — 每场次评分 + 改进建议,弱项会跨场次沉淀到下次的 system prompt
  • 本地优先 + BYOK — 数据不强制上云,LLM 用你自己买的 Key,完全可控

▍三个服务 + 一个 shared,是什么设计?

看 pyproject.toml 顶部注释就明白了:

结构: services/ 下四个平行 Python 包: shared(平台能力)/ api_service(基础 API)/ agent_service(智能体)/ interview_service(模拟面试域)。三服务仅依赖 shared, 彼此零业务互依;模块化单体由 services/main.py 聚合单进程运行。

换句话说,这是一个「模块化单体」(modular monolith) + 「微服务雏形」的双形态架构:

▍两种运行形态

看 services/main.py 头部的注释:

  • 聚合形态(默认) — uvicorn services.main:app --port 8081。三个 router 拼成一个 app,单进程跑,简单。开发首选。
  • 独立形态 — 每个服务有自己的 main.py,可以分别跑在 8081 / 8082 / 8083。这是「微服务雏形」,为以后拆分部署预留接口。
✓
怎么决定用哪种? 开发就聚合,部署压力大就拆。main.py 顶部注释明确写了「三个服务亦可独立启动(见各服务 main.py),此时本聚合入口即微服务网关的雏形」。

▍1. 配置中心 config.py

基于 Pydantic Settings,所有配置都从环境变量或 shared/.env 读:

class Settings(BaseSettings):
    llm_api_base: str = ""             # BYOK:你 LLM 的 base_url
    llm_api_key: str = ""              # BYOK:你的 key(会自动落盘加密)
    llm_model: str = ""                # 默认推理模型
    rag_backend: RAGBackendKind = ...  # local / stepfun
    whisper_model: str = "whisper-1"   # STT 模型
    tts_voice: str = "zh-CN-XiaoxiaoNeural"
    env: str = "dev"                   # dev / prod,影响 CORS / 加密策略
    # ... 几十项

注释里写了端口规划: 默认聚合形态: 前端 8080 / 后端 8081;独立形态: api 8081 / agent 8082 / interview 8083。

▍2. 安全核心 core/security.py + core/secrets.py

这个文件 439 行,把整个应用层的安全都收口了:

  • 文件名清洗 sanitize_filename — 只留 [A-Za-z0-9._-],路径穿越防御。
  • 越界校验 assert_within_dir — 上传文件落盘前用 resolve() + relative_to 校验。
  • SSRF 防御 — 默认拒 127.0.0.0/8、private、link-local、CGNAT、IPv6 等价段。
  • DNS pin — 单次解析后固定 IP 建连,缓解 DNS 重绑定 TOCTOU。
  • API Key 脱敏 redact_api_key — 覆盖主流形态,日志绝不裸出。

加密模块 secrets.py 用 cryptography 的 AES-256-GCM 给 LLM API Key 落盘加密:

# 部署建议:设置环境变量 SECRET_KEY(任意 ≥16 字节字符串)
# 未设置时 services/shared/data/.secret.key 会被自动生成。

生产环境 main.py 会强制要求显式提供 SECRET_KEY,否则启动失败 — 因为数据库迁机器后密文就解不开了。

▍3. 限流 core/ratelimit.py

三种 key:llm(每分钟 LLM 调用)、session_create(创建会话)、default(兜底)。FastAPI 依赖注入风格使用:

dependencies=[Depends(rate_limit_dep(key="llm", limit=60))]

▍4. 能力令牌 core/session_auth.py

这是项目的「轻量鉴权」方案 — 没有注册 / 登录,但每次创建会话(/interview/sessions / /prep/sessions)会下发一个 access_token,只通过 HttpOnly Cookie 下发,响应体不回传。后续改操作(发消息、生成报告)必须带这个 token。

⚠️ 设计上为什么这么做?
因为没有用户体系,所有 API 默认只允许 127.0.0.1(require_local_peer)。 一旦有人绕过本机约束,能力令牌能挡住「列表拿到别人的 session_id 就改他会话」这类攻击。

▍5. LLM 客户端 capabilities/ai/llm/client.py

这是整个项目最核心的 client,后面专门一节讲。简短预告:

  • 支持 OpenAI 兼容协议(几乎所有国产模型都吃这个)
  • 每次请求校验 api_base 是否安全(SSRF 防御)
  • 默认超时 60s,4xx 不重试,429/5xx 指数退避重试 3 次
  • 错误日志脱敏 API Key
  • 流式 / 非流式 / JSON 模式 / 多模态(content 列表)都支持

▍6. 语音能力栈 capabilities/voice/

这个目录是真的「生产级别多供应商抽象」 — 8 个 STT 后端、3 个 TTS 后端、一套统一的凭证模型、统一的选型入口(目录/凭证)。

▍7. 上下文压缩 capabilities/ai/context_manager.py

面试聊到 40 分钟时,上下文可能堆到几十万 token,这个工具帮 LLM 客户端做「早期对话摘要 + 最近 N 条保留」:

def compress_messages(messages, max_tokens, *, keep_recent=20, threshold=0.3):
    """超过预算时压缩为 system 消息 + 最近 N 条对话。"""
    # 总是保留所有 system 消息(面试规则、追问引导等不可丢失)
    # 只在 total > max_tokens * threshold 时触发,避免过度压缩
    # 用户/助手对话仅保留最近 keep_recent 条
    system = [m for m in messages if m.get("role") == "system"]
    rest = [m for m in messages if m.get("role") != "system"]
    trimmed = rest[-keep_recent:]
    summary = {"role": "system", "content": f"[上下文压缩] 早期 {len(rest)-len(trimmed)} 条对话已省略,保留最近 {len(trimmed)} 条。"}
    return system + [summary] + trimmed

▍8. GitHub 集成 capabilities/integrations/github/

面试官「工具调用」能力之一:对候选人的 GitHub profile / repo 做轻量核实(查 README / 提交记录 / 关键文件),结果作为 LLM 追问的参考。client.py 用 PAT,默认无 token 时降级。

▍9. 企业上下文 capabilities/knowledge/company/knowledge.py

内置一份静态的「企业画像」:字节 / 腾讯 / 阿里 / 美团 / 京东 / 滴滴 / 快手 / 拼多多 / 网易 / 华为 / 小米 / 小红书 / Shopify / Stripe / Datadog 等。每家有名称、风格关键词、考察重点、常见追问方向。LLM 出题时会把当前公司的画像注入 system prompt。

▍简历解析全流程

看 routes/resume.py 和 services/resume/parser.py, 走的是一条「安全优先」的管道:

  1. 接收上传(UploadFile),大小限制 RESUME_MAX_UPLOAD_BYTES(默认 10MB)
  2. 文件名走 sanitize_filename 清洗
  3. 用魔数嗅探真实 MIME(PDF 看 %PDF-、DOCX 看 PK\x03\x04),不信客户端 content_type
  4. 落盘后 assert_within_dir 再做越界校验
  5. 调 extract_text_from_file 抽文本(PDF 上限 50 页,DOCX 限条目数和 30MB 解压后体积,防 zip bomb)
  6. 调 parse_resume_with_llm 用 LLM 抽出结构化 CandidateProfile(姓名 / 教育 / 工作 / 技能 / 项目)
  7. 落 SQLite(原文 + 解析结果都存,后者是 JSON 字符串)

▍阶段连通性自检 services/stage_tests.py

这是个细节上很贴心的设计 — 用户在 /settings 改完 LLM key,前端会调这个接口,后端用一个最小的 ping(比如 STT 送一个 1 秒静音)来确认这条线是通的。失败立刻告诉用户,而不是等面试时才发现。

▍招聘平台识别 services/resume/sites.py

支持粘贴招聘 JD 链接,根据 URL 域名推公司名(拉勾 / BOSS / 牛客 / 实习僧…),免去用户手填公司名的麻烦。

▍WebSocket 实时管线 — realtime/ 的 10 个 mixin

整个实时面试的核心是 realtime/ws_handler.py 的 InterviewWSHandler 类。它用 5 个 Mixin 组合实现,每个 Mixin 关注一个职责:

ConnectionLifecycleMixin
握手、心跳(30s 超时 × 3 次 miss)、消息分发、关闭清理。属于「连接层」关注点。
TurnCoordinatorMixin
话轮状态机(IDLE / LISTENING / THINKING / SPEAKING / AWAITING_PLAYBACK)、防并发 turn、busy epoch、turn_busy 锁。
VoicePipelineMixin
选 STT、按句切分、句子级 TTS 队列、回声抑制(_is_echo_of_assistant)、latin 比例过滤。
HintServiceMixin
候选人请求提示词时,LLM 快速生成参考提纲(不影响主对话流)。
ReportSchedulerMixin
面试结束信号触发后台报告生成任务(asyncio.Task),与主 WS 解耦。
其他支撑模块

▍Workflow & 阶段 — 面试的「剧本」

看 services/interview/workflows.py 头注释: 阶段 id / 中文名 / 描述 / 题量上下限只在本模块维护。三种 workflow:

Workflow适用阶段
technical(技术面) 开发岗 身份确认 → 自我介绍 → 基础知识 → 项目深挖 → 技术深挖 → 系统设计 → 情景问题 → 反问 → 总结(共 9 阶段)
hr(HR 面) HR 初面 身份确认 → 自我介绍 → 职业规划 → 团队合作 → 压力问题 → 薪资沟通 → 反问 → 总结
management(管理岗面) 技术 leader / 经理 身份确认 → 自我介绍 → 管理理念 → 团队管理 → 跨部门协作 → 业务思考 → 反问 → 总结

每个阶段有 min_questions / max_questions。Runner 内部维护 phase_idx 和 questions_in_phase,达到上限自动切下一阶段。前端从 options API 拿到 phase_labels 展示进度条。

▍RAG 检索 — 让面试官「懂这家公司」

项目里把 RAG 抽成了 RAGBackend Protocol,有 2 个实现 + 1 个工厂:

📚 LocalEmbeddingRAG
本地 Chroma + 远端 embedding。所有暴露 /embeddings 接口的 LLM 服务商都能用(OpenAI / DeepSeek / 智谱 / 阿里百炼…)。
落盘: services/shared/data/chroma。
文档切片: _build_documents 在 _kb_data.py。
☁️ StepFunRetrievalRAG
StepFun(阶跃星辰)托管 vector_stores,检索走 tools[].type=retrieval。
适用: 你已经在用 StepFun,直接复用它的向量库。
🏭 factory.py
工厂方法根据 settings.rag_backend 选择具体后端。
失败降级: 启动时若 ensure_index() 失败,只 warn 不抛错,空库继续跑。

检索入口在 CompanyKnowledgeRAG.query_for_company(company_id, top_k=4)。它的结果会注入到 PromptAssembler.build_system_prompt,让 LLM 在出题和追问时能引用「这家公司通常怎么考」。

▍报告 & 成长闭环

报告生成由 services/interview/report.py 负责,12KB 单独成文件,逻辑量很大。核心流程:

  1. 用 runner.tools 收集本场次的工具调用痕迹(查了哪些 GitHub repo、问过哪些项目…)
  2. 汇总候选人所有 messages + 阶段推进 + 标注的薄弱点
  3. LLM 生成结构化报告(总体评分 + 维度分 + 优势 + 待提升 + 改进建议 + 复盘问题清单)
  4. 报告落 session.report JSON,同时把 weak_skills / common_mistakes / training_plan 写到 growth_records 表
  5. learning.py 维护 services/shared/data/system_learning.json(带 fcntl 文件锁,防并发写),作为下次面试 system prompt 的「跨场次记忆」
🔁 自我成长闭环
这是项目里 PRD 4.7「自我成长」的反哺闭环实现: 你第一次面试暴露的薄弱点,会被带进第二次面试的 system prompt,让 Agent 在还没问之前就知道「这家公司/这岗位的人上次栽在哪」。

▍视觉子 Agent agents/vision/agent.py

这是个轻量子 Agent — 它做的事情是:在用户开启摄像头时,定时(每 3s)抓一帧 JPEG,分析候选人「有没有看镜头 / 表情紧张度 / 视线方向」,把分析结果作为额外字段塞到 LLM 输入。前端 VideoPanel.tsx 也用浏览器原生 FaceDetector 自己做了一份,前后端互为冗余。

▍面试统筹 Agent agents/orchestrator.py

这是个「多 Agent 协调者」,目前职责比较克制:

  • build_context_prefix() — 合并 vision / 后续可能的 audio 等子 Agent 快照
  • build_silence_nudge(personality, strictness, phase) — 候选人沉默太久时,按人格 + 严格度生成「请继续说」的一句话(分三档,同档内随机,避免句句相同)

▍CI 流水线(.gitlab-ci.yml)

每个包独立 job
shared / api_service / agent_service / interview_service 各自跑:
  1. ruff check {包}/ — 风格
  2. mypy {包}/ --ignore-missing-imports — 类型
  3. pytest {包}/tests -q — 单元测试
任何一个失败该 job 红 ✗
聚合 job
aggregate 跑全量回归 + 覆盖率(≥ 40% 守门),
frontend 跑 tsc --noEmit + npm run lint + npm run build + npm audit --audit-level=high。
🔧 工具版本固定
CI 里 ruff==0.15.20 / mypy==2.1.0 全部锁版。注释里写得很清楚:ruff 0.16 默认规则集扩张会导致 252 错 — 这是非常「被现实教育过」的工程实践。

🌱 项目最值得品味的几处设计
  1. 三阶段处理器可独立配 LLM — 这是国内同类产品很少见的设计,真实可降级
  2. 能力令牌 + 仅本机 — 没有用户体系也能挡住最常见的横向移动
  3. SSRF 全方位防御 — DNS pin / 段黑名单 / 端口白名单 / httpx transport 自定义
  4. 跨场次自我成长 — system prompt 注入历史洞察,Agent 越用越懂你
  5. Pipeline 全部 asyncio.to_thread 卸载同步 IO — WS 不抖的关键
  6. WebSocket Mixin 拆分 — 5 个 mixin 把 10 个文件的关注点拆得很清楚
  7. 运维向注释 — 每处非显然决策都有解释(为什么锁版 / 为什么接受某个漏洞 / 为什么这条 SQL 这么写)
总结

★RealMock 全景一句话

RealMock 是一个把 「真实面试」 复刻到本机的 AI 模拟器:后端是 模块化单体(shared 平台层 + 三个业务包), 跑在 FastAPI + SQLAlchemy + Chroma + WebSocket 上;前端是 Next.js 15 + React 19, 走 App Router,主打 音视频 + 3D avatar + 流式对话。它把 简历、岗位、企业风格、阶段化追问、工具调用、报告评分、跨场次成长 串成了一个完整闭环,而且 完全本地优先 + BYOK。

接手它不需要从零理解 — 你只需要按这份导览的节奏: 先看架构 → 再看核心 (Runner / Agent / WS) → 然后按需钻细节。 一周之内应该就能开始提 PR 了。
